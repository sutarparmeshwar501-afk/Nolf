# Nolf Corporate Website — Outcomes

- [x] **Responsive shell and brand presentation** — Create a responsive global shell with a simple NOLF wordmark, desktop navigation, accessible mobile navigation, footer, and consistent black-and-white visual styling. The visual style should use white backgrounds, black typography, subtle grey borders, generous whitespace, clean layouts, restrained animations, and excellent mobile responsiveness. Avoid excessive cards, colorful gradients, stock-looking illustrations, and copied Meta branding. Keep Nolf and INDlop as separate brands; present INDlop as a product of the Nolf brand, without claiming a registered legal entity owns INDlop unless that ownership has been legally established.
- [x] **Home and featured INDlop product** — Build the Home page with the exact headline “Building technology for what comes next.” and supporting text “Nolf is a technology brand focused on building thoughtful digital products and experiences.” Include a dedicated Products section featuring INDlop as the first product. The INDlop product card and its primary action must both link directly to https://indlop.com.
- [x] **About Nolf, Products, and Technology pages** — Create working pages for About Nolf, Products, and Technology that describe Nolf’s product focus and technology approach using restrained, factual corporate messaging without unsupported claims.
- [x] **Newsroom and Careers pages** — Create working Newsroom and Careers pages with honest empty-state or informational content and no fabricated announcements, openings, or nonfunctional actions.
- [x] **Contact page** — Create a working Contact page using valid contact options only, without a backend form, fake address, or unusable controls.
- [x] **Privacy Policy and Terms of Service pages** — Create working Privacy Policy and Terms of Service pages with clearly structured baseline content and appropriate links, avoiding invented company details.
- [x] **Metadata, links, and accessibility** — Add route-specific page titles and meta descriptions. Ensure links lead to valid destinations and the mobile navigation works. Use semantic structure, keyboard usability, visible focus states, descriptive links, and accessibility basics throughout. Do not use placeholder links, fake company addresses, fake testimonials, invented company statistics, or nonfunctional buttons.
- [x] **Next.js + Tailwind boilerplate** — Provide a complete Next.js-compatible project structure using Tailwind CSS, restrained animations, mobile responsiveness, and no backend, authentication system, database, paid services, or unnecessary dependencies.
- [x] **Static publishing build contract** — Configure a self-contained pinned pnpm install/build command and a static output directory whose root contains `index.html`. Use a Next.js static export, keep publishing on the static host without introducing a backend, and verify the exported pages and manifest.
- [x] **Validation and non-deployment** — Run the available build and validation checks, fix any errors, and report the exact files changed, routes created, tests performed, and any remaining setup required. Do not change DNS without explicit approval.
